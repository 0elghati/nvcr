# DCVC-UF under `nvcr.fx.v1` (RTX 4070, 2026-11-12)

Branch `feat/dcvcuf-fx`, stacked on `feat/fx-codec-helpers` (#253). One RTX 4070 (SM 8.9, driver 580.178.04),
Ubuntu 24.04, CUDA 12.8, TensorRT 10.9, ONNX Runtime 1.26.0 (CPU), Triton 3.5.1 for the ahead-of-time kernels,
PyTorch 2.9.1 and ONNX 1.23.2 for the exports.

## What runs

- **Profile:** `nvcr.fx.v1` ([spec](../docs/spec/numerics-fx-v1.md)), unchanged; DCVC-UF needed no new op. Its WSiLU
  chunk-add over four interleaved channels is the spec's grouped GEMM (`group` 4).
- **Programs:** thirteen DCVC-UF HT-S stages exported by `scripts/backends/dcvcuf/export_fx_programs.py` from the pinned
  cvpr2026 checkpoints with `configs/numerics/dcvcuf-fx.json`: the I-frame's prior, three spatial steps and synthesis;
  the chunk references after an I-frame (`p_reference_frame`), after a chunk (`p_reference_memory`) and after a
  feature-memory reset (`p_reset_reference`, the exact picture of the last frame); the chunk's prior, which returns
  all its entropy indexes (255 where the element is skipped: scale at or below the threshold, as upstream), three
  spatial steps that refine only the means, and the decoded feature.
- **FP16 stages** (nothing reads them back): I-frame analysis and hyper analysis, the chunk's analysis from its eight
  8-bit frames and the exact context (`p_encode`), its hyper analysis, and its eight pictures from the exact feature
  (`p_display`, 8-bit 4:2:0). Built strongly typed by `scripts/backends/dcvcuf/add_fx_plans.py`. In these graphs the
  chunk-add sums contiguous channel blocks (rows of the conv before it reordered), the same sums as upstream's strided
  slices, which TensorRT copies: 9 % faster decoding.
- **Codec:** `src/dcvcuf/fx_session.cpp` runs the stages through the generic provider session. Entropy coding is
  DCVC-UF's own rANS, payloads keep the UFI1/UFP1 syntax, the chunk schedule is unchanged (reset interval 32, skip
  threshold 0), and intra units carry the numerics identity (`codec::StreamNumerics`, #253).
- **Providers:** TensorRT (plans from the programs, plus 10 GEMM kernel variants DCVC-UF needs) and ONNX Runtime CPU
  (NVCR's reference executor).

## Conformance

| Check | Result |
|---|---|
| Exported programs vs the research exact codec (`exactrt.uf`, hybrid + coarse WSiLU + reset-head shifts), chained random inputs at 240x240 (`dcvc-robust/scripts/fx_parity_uf.py`) | 13/13 stages, every output bit-identical |
| TensorRT plans vs the CPU reference, built for 64x64 to 240x240, checked at 240x240 and 176x144 (`nvcr_fx_tensorrt_dcvcuf`) | 13/13 stages bit-identical |
| The bundle's TensorRT plans vs the CPU reference at 1920x1080 and 176x144 | 13/13 stages bit-identical at both sizes |
| Cross-provider: TensorRT encode, BasketballDrive 1080p, QP 21, I + one chunk; TensorRT decode vs ONNX Runtime CPU decode | 9/9 frames decode, every unit ending at the encoder's rANS state; I picture byte-identical; P pictures (FP16, not in the profile) within 1 code value (63.4-64.7 dB between the decodes) |
| Feature-memory reset: 49 frames, one I-frame, reset at the chunk ending at frame 32, BasketballDrive QP 21 | the two chunks after it 32.94 / 32.83 dB (YUV 6:1:1), native 32.92 / 32.84 dB |
| CPU Release / TensorRT + ONNX Runtime Release tests | 33/33 / 37/37 |

The ONNX Runtime CPU decode takes about 25 minutes for these nine frames.

## Rate-distortion against NVCR native (TensorRT)

33 frames (I + 4 chunks, no second I-frame), QPs 0/21/42/63, PSNR-YUV 6:1:1 (mean over frames), rate = stream bytes,
BD by pchip.

| Sequence | BD-rate fx vs native |
|---|---|
| BasketballDrive 1080p | -1.53 % |
| Kimono 1080p | -1.75 % |
| Jockey 1080p | -1.48 % |

At equal QP fx is 0.02-0.08 dB higher at almost the same rate. The cause is not traced; native converts its pictures
to 8 bits after rounding in FP16, fx in FP32, which may contribute. The research exact codec, at the same settings,
measures +0.09 % against a float mirror of upstream (`dcvc-robust/RESULTS-uf.md`).

## Speed (diagnostic)

BasketballDrive 1080p, QP 21, 49 frames with one I-frame, codec interval from the CLI after the first output, three
runs each on an otherwise idle machine (no other GPU process, no other busy CPU process), agreeing within 1.2 %:

| | Encode | Decode |
|---|---|---|
| native (TensorRT) | 113.5 fps | 90.9 fps |
| `nvcr.fx.v1` | 52.3 fps | 60.2 fps |
| research exact codec (Python + Triton; upstream's fused CUTLASS display) | 60.7 fps | 77.8 fps |

A decoded chunk takes about 125 ms: the exact stages about 75 ms (as fast as the research codec's), host work about
10 ms (rANS, indexes, frames) and the FP16 display about 35 ms. The display network costs 32-34 ms in TensorRT FP16,
also as native's own reconstruction plan (34.3 ms); the research codec reaches 18.9 ms with upstream's fused CUTLASS
kernels (39.9 ms in PyTorch), which are not a provider's implementation.

## Reproducing

Pinned inputs: upstream `microsoft/DCVC` `cbdae87a5445114cdc7f48816da63ea80bdeac40`; checkpoints
`cvpr2026_image.pth.tar` (`b3b900de23f30e4fc437010ddffe6a5413a56d6cfd97fb6235adbcd2b6973302`) and
`cvpr2026_video_hts.pth.tar` (`565607d84943ee79072a5760d34a200d5724b4bb72c6bc24bfab41e8ae4f5f47`), checked by the
scripts. `configs/numerics/dcvcuf-fx.json` `73ee167b579af338fb09e31b82255a1cb3499d8aeac18e972212d12bcb8f580e`.

1. Programs (any machine, deterministic: float64 on the CPU; SHA-256 of the 27 files' `sha256sum` list
   `61516f95ae579921c74fb2a86326f3eddc5774840c59b895f23b5f0139bcb652`):

   ```text
   python scripts/backends/dcvcuf/export_fx_programs.py --dcvcuf-root <DCVC> --checkpoints <dir> \
     --config configs/numerics/dcvcuf-fx.json --output-dir <programs>
   ```

2. The DCVC-UF TensorRT bundle, 1080p profile (`export_tensorrt_stages.py`, see `scripts/backends/dcvcuf/README.md`;
   here built `--from-export` from the RTX 4070 export of NVCR `388c45e5`, `tables.bin`
   `9c73455ae61a293956f4d0032f9a8e4cad1ff6a81676edb31cc0853047561616`).
3. The fx stages: `cmake -DNVCR_ENABLE_TENSORRT=ON -DNVCR_TENSORRT_FX_PYTHON=<python with Triton 3.5.1>`, then

   ```text
   python scripts/backends/dcvcuf/add_fx_plans.py --bundle <bundle> --programs <programs> --dcvcuf-root <DCVC> \
     --checkpoints <dir> --nvcr-fx-plans <build>/nvcr-fx-plans [--onnx-dir <dir for ONNX Runtime>]
   ```

4. Run: `nvcr encode --codec dcvc-uf --numerics nvcr.fx.v1 --gop-size 65528 ...`; decoders adopt the stream's profile.

The input shifts come from the research setting `uf_hybrid_k1.json` plus the reset head's, which the research clips
never reached and which `dcvc-robust/scripts/uf_arange_reset.sh` measures with the same calibration method. Without
them the reset head clips its GEMM inputs.

## Not checked

- A second GPU (RTX 5060), and any QNN or AMD implementation.
- An ONNX Runtime CPU encode decoded on TensorRT; a cross-provider decode longer than nine frames.
- BD-rate against pinned upstream under NVCR (the comparison above is against NVCR native).
- Frame sizes other than the 1080p profile's range (64x64 to 1920x1088); bundles are local, not published.
